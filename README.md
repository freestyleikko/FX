# FX 自動売買システム(ロジック実装)

USD/JPY・EUR/JPY・GBP/JPY の3通貨ペアを対象に、ロング・ショートを組み合わせて
ポートフォリオを構築する自動売買ロジックです。**金利差(キャリー/スワップ)を
シグナルと損益の両方に組み込み**、レバレッジは**自己資金の5倍まで**に制限します。

> ⚠️ 現時点では証券会社の API 契約が無いため、**ロジックとバックテストのみ**の実装です。
> 実弾運用時は `fx_trader/broker.py` の `BrokerGateway` インターフェースを
> 実際の API クライアントで実装して差し替えてください。

## 構成

```
fx_trader/
├── config.py      # 通貨ペア・政策金利・レバレッジ上限などの設定
├── models.py      # Position / Signal / Order などのデータ型
├── indicators.py  # EMA / RSI / ATR / モメンタム等のテクニカル指標
├── carry.py       # 金利差(キャリー)スコアとスワップポイント計算
├── strategy.py    # トレンド + キャリー + 過熱フィルタの複合シグナル生成
├── portfolio.py   # ボラティリティ調整型の資金配分とレバレッジ制限(≤5倍)
├── risk.py        # ATRストップ/テイクプロフィット・ドローダウン遮断
├── backtest.py    # スワップ損益込みのバックテストエンジン
├── data.py        # 合成データ生成器と CSV ローダー
└── broker.py      # 発注ゲートウェイの抽象IF(将来のAPI接続用・現状ペーパー実装)

examples/run_backtest.py  # バックテスト実行サンプル
tests/                    # ユニットテスト
```

## ロジック概要

各ペアごとに **-1(フルショート)〜 +1(フルロング)** のスコアを算出し、
それをポートフォリオ全体の建玉に変換します。

### 1. シグナル(strategy.py)

| 成分 | 内容 | 重み(初期値) |
|---|---|---|
| トレンド | EMA(20/60) クロスの乖離 + 90日モメンタムを tanh 正規化 | 0.6 |
| キャリー | 政策金利差(対円)を正規化。金利差が大きいペアほどロング優位 | 0.4 |
| 過熱フィルタ | RSI(14) が 70 超で買い縮小、30 未満で売り縮小 | 乗算 |

- 金利差がプラス(例: USD 金利 > JPY 金利)のペアはロングでスワップ受取り、
  ショートでは支払いになるため、**キャリー成分がショートシグナルへのブレーキ**として働きます。
- スコアの絶対値が `entry_threshold`(初期 0.15)未満はノーポジション扱いで、
  細かい往復売買を防ぎます(ヒステリシス付き)。

### 2. 資金配分(portfolio.py)

- 各ペアの実現ボラティリティの逆数で配分(リスクパリティ的)し、
  スコアを乗じて目標ウェイトを決定。
- **総建玉(グロス)が自己資金の5倍を超える場合は比例縮小**して必ず 5 倍以内に収めます。
- 1ペアあたりの上限(初期 2.5 倍)も併用し、一極集中を防ぎます。

### 3. リスク管理(risk.py)

- ATR×2.5 の逐次ストップロス、ATR×5 のテイクプロフィット
- 口座残高が高値から 15% 下落したら全決済して新規建てを一時停止(サーキットブレーカー)
- 1日の損失が資金の 3% を超えた日は新規建て禁止

### 4. スワップ損益(carry.py / backtest.py)

- 日次で `建玉 × 金利差 / 365` をスワップとして損益に計上
  (ロングで金利差プラスなら受取り、ショートなら支払い)。
- 業者スプレッドを想定した `swap_haircut`(受取りは減額・支払いは増額)も設定可能。

## 使い方

```bash
pip install -r requirements.txt

# 合成データでバックテスト
python examples/run_backtest.py

# 自前の CSV(date,open,high,low,close)を使う場合
python examples/run_backtest.py --csv-dir path/to/csvs

# 過去1年(2025/7〜2026/7)の実勢レート水準に基づくシナリオ検証
python examples/scenario_past_year.py

# アグレッシブ設定(レバレッジ上限5倍まで使い切る。想定最大DD約30%)
python examples/scenario_past_year.py --aggressive

# レバレッジ上限を引き上げて検証(法定上限25倍まで)
python examples/scenario_past_year.py --leverage 10

# ストレステスト: 2024年夏の円キャリー巻き戻し局面(5倍/10倍/25倍比較)
python examples/scenario_stress_2024.py
```

### 設定プロファイル(過去1年シナリオでの推定値)

| | standard(既定) | aggressive 5倍 | aggressive 10倍 |
|---|---|---|---|
| 実効レバレッジ | 〜2倍程度 | 上限5倍に張り付き | 上限10倍に張り付き |
| 順風の年(2025/7〜2026/7) | +9%前後 | +33%前後 | +66%前後 |
| 同・最大DD | -4% | -12% | -23% |
| 逆風の年(2024年下期) | — | **-28% / DD-34%** | **-51% / DD-59%** |

グロスレバレッジが含み損益の変動で上限を超えた場合は、日次で強制的に
比例縮小して必ず上限以内に戻します。既定の上限は5倍で、
`SystemConfig.aggressive(max_gross_leverage=...)` で法定上限25倍まで
引き上げられます(バリデーションで25倍超は拒否)。

⚠️ 本バックテストは追証・強制ロスカット(証拠金維持率による自動決済)や
週明けギャップの滑りをモデル化していません。高レバレッジでの実運用では
モデルより悪い結果(全損含む)になり得ます。

テスト:

```bash
python -m pytest tests/ -v
```
